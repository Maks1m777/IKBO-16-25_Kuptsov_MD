# VFS Emulator

Эмулятор командной строки UNIX-подобной ОС с виртуальной файловой системой (VFS).

## Запуск

```bash
python3 vfs_emulator.py [-v PATH] [-s PATH]
```

### Параметры командной строки (Этап 2)

| Флаг      | Длинная форма   | Значение                                   |
|-----------|-----------------|--------------------------------------------|
| `-v PATH` | `--vfs PATH`    | Путь к физическому VFS (CSV-файл).          |
| `-s PATH` | `--script PATH` | Путь к стартовому скрипту команд эмулятора. |

При запуске в **stderr** печатается отладочная сводка параметров и структура
загруженной VFS.

## Виртуальная файловая система (Этап 3)

* Все операции с VFS выполняются **в памяти**; исходный CSV не распаковывается
  и не модифицируется.
* Источник — CSV: вложенность = канонический путь в колонке `path`, тип =
  `type` (`dir`/`file`), содержимое (в т.ч. двоичное) = base64 в `content`.
* Без `--vfs` строится VFS по умолчанию (`default_vfs`).
* `vfs-init` заменяет текущую VFS на default и очищает физическое представление.
* Битые строки валидного CSV → warning в stderr + пропуск; непригодный заголовок
  или отсутствующий файл → stderr + код выхода `1`.

## Основные команды (Этап 4)

Реальная логика поверх дерева VFS и рабочего каталога `STATE.cwd`.

| Команда              | Описание |
|----------------------|----------|
| `ls [-a] [-l] [PATH...]` | Листинг. Без аргументов — текущий каталог. `-a` — показывать скрытые, `-l` — длинный формат (права/владелец/размер-каталога **симулированы**). Имена выводятся по одному на строку (стиль `ls -1`). Несуществующий путь → stderr, продолжение. Неизвестный флаг → stderr, команда не выполняется. Поддержан терминатор `--`. |
| `cd [PATH]`          | Смена рабочего каталога. Относительные пути — от cwd. **Без аргумента → `/`** (понятия `$HOME` в модели VFS нет). Ошибки (нет пути / не каталог / лишние аргументы) → stderr, cwd не меняется. |
| `cat PATH...`        | Побайтовый дамп файлов (точная имитация POSIX `cat`, **без** добавления перевода строки). Без аргументов → ошибка (чтение stdin недоступно, т.к. stdin занят REPL). Каталог / отсутствующий путь → stderr, продолжение. |
| `pwd`                | Печатает текущий рабочий каталог. |
| `vfs-init`           | (Этап 3) Сброс VFS к default + очистка физического представления. |
| `exit`               | (Этап 1) Завершение работы. |

> Изменяющие VFS команды `mkdir`/`touch` — Этап 5.

### Замечания по совместимости с POSIX

* `cd` без аргумента переходит в `/`, а не в `$HOME`.
* `cat` без аргумента завершается ошибкой, а не читает stdin.
* `ls` всегда выводит по одному имени на строку (как `ls -1`), а не колонками.
* `cat` не добавляет trailing newline, поэтому вывод файла без `\n` склеится со
  следующим промптом — это ожидаемое поведение.

## Режимы работы

* **Интерактивный REPL**: приглашение `VFS$ `; Ctrl+D/EOF → выход, Ctrl+C →
  прерывание строки (возврат к приглашению).
* **Скриптовый режим** (`--script`): последовательное выполнение с имитацией
  диалога (печатается и «ввод», и «вывод»); пустые и ошибочные строки
  пропускаются; `exit` останавливает выполнение; отсутствующий файл → код `1`;
  Ctrl+C → код `130`.

## Обработка ошибок и сигналов

* Неизвестная команда / битый путь / не-каталог / неизвестный флаг → stderr;
  выполнение продолжается.
* Пустой ввод / пустая строка в скрипте → игнорируется.
* Ctrl+C (интерактив) → прерывание строки; Ctrl+D/EOF (интерактив) → выход.
* Ctrl+C (скрипт) → код `130`.
* Отсутствующий `--script`/`--vfs`, непригодный заголовок CSV → код `1`.
