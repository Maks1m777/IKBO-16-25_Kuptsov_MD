# VFS Emulator

Эмулятор командной строки UNIX-подобной ОС с виртуальной файловой системой (VFS).

## Запуск

```bash
python3 vfs_emulator.py [-v PATH] [-s PATH]
```

### Параметры командной строки

| Флаг      | Длинная форма   | Значение                                   |
|-----------|-----------------|--------------------------------------------|
| `-v PATH` | `--vfs PATH`    | Путь к физическому VFS (CSV-файл).          |
| `-s PATH` | `--script PATH` | Путь к стартовому скрипту команд эмулятора. |

При запуске в **stderr** печатается отладочная сводка параметров и структура
загруженной VFS:

```
[config] vfs_path    = vfs_data/deep.csv
[config] script_path = <not set>
[config] mode        = interactive
[vfs] source = vfs_data/deep.csv
[vfs] nodes  : dirs=8 files=4
[vfs] structure:
/ [dir]
  etc [dir]
    hosts [file] (0 bytes)
  home [dir]
    alice [dir]
      projects [dir]
        blob.bin [file] (6 bytes)
        notes.txt [file] (5 bytes)
        src [dir]
          main.c [file] (5 bytes)
  var [dir]
    log [dir]
```

## Виртуальная файловая система (Этап 3)

* Все операции с VFS выполняются **в памяти**; исходный CSV не распаковывается
  и не модифицируется.
* **Источник** — CSV-файл. Вложенность дерева кодируется каноническим
  абсолютным путём в колонке `path`; тип узла — в `type` (`dir`/`file`);
  содержимое файлов (в т.ч. двоичное) — в `content` в формате **base64**.
* Если `--vfs` **не указан**, VFS создаётся **по умолчанию** в памяти
  (`default_vfs()`): каталоги `/home/user`, `/etc`, `/tmp` и файлы
  `welcome.txt`, `motd`.
* Промежуточные каталоги создаются автоматически по путям; порядок строк в
  CSV не важен. Повреждённые строки (неверный base64, неизвестный `type`,
  спуск внутрь файла, дубликаты) отбрасываются с предупреждением в stderr,
  а валидная часть дерева загружается.
* Непригодный заголовок CSV или отсутствующий файл `--vfs` → ошибка в stderr
  и код выхода `1`.

### Служебная команда `vfs-init`

Заменяет текущую VFS на VFS по умолчанию и **очищает физическое
представление** (сбрасывает связь с CSV-источником и рабочий каталог в `/`).
Не принимает путь; лишние аргументы игнорируются с предупреждением. Результат
(дамп нового дерева) печатается в stdout.

## Режимы работы

* **Интерактивный REPL** (скрипт не задан): приглашение `VFS$ `;
  Ctrl+D / EOF завершает работу, Ctrl+C прерывает текущую строку.
* **Скриптовый режим** (`--script`): команды выполняются последовательно,
  печатается и «ввод», и «вывод» (имитация диалога); пустые и ошибочные
  строки пропускаются; `exit` останавливает выполнение; отсутствующий файл
  → код `1`; Ctrl+C → код `130`.

## Поддерживаемые команды

| Команда           | Этап | Описание                                              |
|-------------------|------|-------------------------------------------------------|
| `ls [args...]`    | 1    | Заглушка: выводит имя команды и аргументы.             |
| `cd [args...]`    | 1    | Заглушка: выводит имя команды и аргументы.             |
| `exit`            | 1    | Завершает работу эмулятора.                            |
| `vfs-init`        | 3    | Сбрасывает VFS к умолчанию, очищает физическое предст. |

> Реальная логика `ls`/`cd` и команды `cat`/`pwd` — Этап 4; изменяющие VFS
> команды `mkdir`/`touch` — Этап 5.

## Обработка ошибок и сигналов

* Неизвестная команда → stderr; в интерактиве продолжает работу, в скрипте
  пропускает строку.
* Пустой ввод / пустая строка в скрипте → игнорируется.
* Ctrl+C (интерактив) → прерывание строки; Ctrl+D/EOF (интерактив) → выход.
* Ctrl+C (скрипт) → код `130`.
* Отсутствующий `--script` или `--vfs`, непригодный заголовок CSV → код `1`.
* Повреждённые строки валидного CSV → предупреждение в stderr + пропуск.

## Структура репозитория

```
vfs-emulator/
├── vfs_emulator.py        # Эмулятор: REPL + конфигурация + VFS + vfs-init
├── README.md
├── .gitignore
├── vfs_data/              # CSV-источники VFS (Этап 3)
│   ├── minimal.csv
│   ├── several_files.csv
│   ├── deep.csv           # >=3 уровней вложенности
│   ├── broken_header.csv  # негативный тест (заголовок)
│   └── broken_rows.csv    # негативный тест (строки)
├── vfs_scripts/           # Стартовые скрипты эмулятора (списки команд VFS)
│   ├── basic.txt
│   ├── with_errors.txt
│   ├── exit_mid.txt
│   └── vfs_demo.txt       # демо всех команд + vfs-init + ошибки
├── os_scripts/            # Bash-скрипты реальной ОС: вызовы эмулятора
│   ├── test_no_args.sh
│   ├── test_vfs_only.sh        # (обновлён на Этапе 3: реальный CSV)
│   ├── test_script_only.sh
│   ├── test_both.sh            # (обновлён на Этапе 3)
│   ├── test_short_flags.sh     # (обновлён на Этапе 3)
│   ├── test_bad_script.sh
│   ├── test_vfs_load.sh        # различные варианты VFS (загрузка)
│   ├── test_vfs_commands.sh    # команды + VFS + оба режима
│   ├── test_vfs_errors.sh      # обработка ошибок VFS
│   └── run_all_stage3.sh       # мастер-скрипт этапа 3
└── tests/
    └── test_stage1.sh     # демонстрация интерактивного режима (Этап 1)
```

## Как прогнать тесты

```bash
# Этап 3 целиком:
bash os_scripts/run_all_stage3.sh

# Отдельные аспекты:
bash os_scripts/test_vfs_load.sh
bash os_scripts/test_vfs_commands.sh
bash os_scripts/test_vfs_errors.sh

# Регрессия параметров (Этап 2, теперь с реальной загрузкой VFS):
bash os_scripts/test_vfs_only.sh
bash os_scripts/test_both.sh
bash os_scripts/test_short_flags.sh
```
