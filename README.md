# VFS Emulator

Эмулятор командной строки UNIX-подобной ОС с виртуальной файловой системой (VFS).

## Запуск

```bash
python3 vfs_emulator.py [-v PATH] [-s PATH]
```

### Параметры командной строки (Этап 2)

| Флаг      | Длинная форма   | Значение                                   |
|-----------|-----------------|--------------------------------------------|
| `-v PATH` | `--vfs PATH`    | Путь к физическому VFS (CSV-файл).          |
| `-s PATH` | `--script PATH` | Путь к стартовому скрипту команд эмулятора. |

При запуске в **stderr** печатается отладочная сводка параметров и структура
загруженной VFS.

## Виртуальная файловая система (Этап 3)

* Все операции с VFS выполняются **в памяти**; исходный CSV не распаковывается
  и не модифицируется.
* Источник — CSV: вложенность = канонический путь в колонке `path`, тип =
  `type` (`dir`/`file`), содержимое (в т.ч. двоичное) = base64 в `content`.
* Без `--vfs` строится VFS по умолчанию (`default_vfs`).
* `vfs-init` заменяет текущую VFS на default и очищает физическое представление.
* Битые строки валидного CSV → warning в stderr + пропуск; непригодный заголовок
  или отсутствующий файл → stderr + код выхода `1`.

## Основные команды (Этап 4)

| Команда              | Описание |
|----------------------|----------|
| `ls [-a] [-l] [PATH...]` | Листинг VFS. `-a` — скрытые, `-l` — длинный формат (права/владелец/размер-каталога **симулированы**). Имена по одному на строку (`ls -1`). Несуществующий путь → stderr, продолжение. Неизвестный флаг → stderr, команда отменена. Поддержан `--`. |
| `cd [PATH]`          | Смена рабочего каталога; относительные пути — от cwd. **Без аргумента → `/`**. Ошибки → stderr, cwd не меняется. |
| `cat PATH...`        | Побайтовый дамп файлов (**без** trailing newline, как POSIX). Без аргументов → ошибка (stdin занят REPL). Каталог / нет пути → stderr, продолжение. |
| `pwd`                | Текущий рабочий каталог. |

## Дополнительные команды (Этап 5) — мутация VFS в памяти

`mkdir` и `touch` изменяют **только** in-memory дерево `STATE.vfs`
(`children` + индекс `_index`). CSV-источник на диске не трогается, а
`STATE.vfs_source` при мутациях **не** сбрасывается (сброс делает только
`vfs-init`): мутация — это не «замена VFS», а правка живого дерева, поэтому
после `mkdir`/`touch` дерево расходится с CSV, и это расхождение нигде не
сериализуется. Доказательство — в `os_scripts/test_stage5.sh` (совпадение
SHA-256 CSV до/после + неперсистентность мутаций в отдельном процессе).

| Команда                 | Описание |
|-------------------------|----------|
| `mkdir [-p] [-v] PATH...` | Создание каталогов. `-p` — промежуточные каталоги (цель-каталог → тихий успех); `-v` — печатать `mkdir: created directory '<канон. путь>'` для каждого созданного; `--` — терминатор. Без `-p`: существующая цель → `File exists`; нет родителя → `No such file or directory`; родитель-файл → `Not a directory`. С `-p`: спуск сквозь файл → `Not a directory`; цель-файл → `File exists`. Неизвестный флаг → stderr, команда отменена. |
| `touch PATH...`         | Создание/«обновление» файлов. Флагов времени **нет** (модель VFS их не хранит): `-c/-a/-m/-r` → `invalid option` + отмена; `--` — терминатор для имён с дефисом. Новый файл → **пустой** (`0` байт); существующий файл → тихий no-op; существующий каталог → `Is a directory`; нет родителя → `No such file or directory`; родитель-файл → `Not a directory`. Родителей **не** создаёт (в отличие от `mkdir -p`). |

> `cat` по файлу, созданному `touch`, печатает **ничего** (пустой файл +
> POSIX-семантика `cat` без перевода строки) — ожидаемое поведение.

## Служебные / базовые команды

| Команда     | Этап | Описание |
|-------------|------|----------|
| `vfs-init`  | 3    | Сброс VFS к default + очистка физического представления (и cwd → `/`). |
| `exit`      | 1    | Завершение работы. |

## Замечания по совместимости с POSIX

* `cd` без аргумента → `/`, а не `$HOME` (понятия `$HOME` в модели VFS нет).
* `cat` без аргумента → ошибка, а не чтение stdin (stdin занят REPL).
* `ls` всегда выводит по одному имени на строку (как `ls -1`).
* `cat` не добавляет trailing newline → вывод файла без `\n` склеится со
  следующим промптом.
* `touch` не поддерживает флаги обновления времени; неизвестные флаги
  отменяют команду (согласованно с `ls`/`mkdir`).
* `-v` у `mkdir` печатает канонический абсолютный путь созданного каталога.

## Режимы работы

* **Интерактивный REPL**: приглашение `VFS$ `; Ctrl+D/EOF → выход, Ctrl+C →
  прерывание строки.
* **Скриптовый режим** (`--script`): последовательное выполнение с имитацией
  диалога; пустые и ошибочные строки пропускаются; `exit` останавливает;
  отсутствующий файл → код `1`; Ctrl+C → код `130`.

## Обработка ошибок и сигналов

* Неизвестная команда / битый путь / не-каталог / неизвестный флаг / дубликат
  mkdir / touch-каталог → stderr; выполнение продолжается.
* Пустой операнд у `mkdir`/`touch` → stderr.
* Пустой ввод / пустая строка в скрипте → игнорируется.
* Ctrl+C (интерактив) → прерывание строки; Ctrl+D/EOF (интерактив) → выход.
* Ctrl+C (скрипт) → код `130`.
* Отсутствующий `--script`/`--vfs`, непригодный заголовок CSV → код `1`.
